# Как собрать перевод-мод

Инструкция для моддера: перевели мод (или ванилу) — как из этого сделать мод,
который видно в лаунчере и который работает в игре.

## Что такое перевод-мод

Это **отдельный мод**, внутри которого лежит только перевод: файлы
`localisation/<язык>/*.yml` с теми же ключами, что у оригинала, но с текстом на
нужном языке. Сам мод-цель и файлы игры не меняются — ключи совпадают, поэтому
игра берёт строку из перевода.

Из этого следует главное: **не нужно копировать весь мод**. Один файл описания,
папка `localisation` и всё.

## Что должно быть в файлах перевода

Инструмент делает это сам, но знать полезно — иначе непонятно, что ломается:

* имя файла оканчивается на `_l_russian.yml` (для русского) — суффикс должен
  совпадать с языковой базой, иначе игра файл не прочитает;
* первая строка файла — `l_russian:` (именно она задаёт язык, а не имя папки);
* кодировка UTF-8 **с BOM**; переводы строк LF или CRLF — без разницы;
* ключи и разметка (`$STATE$`, `§Y…§!`, `£army_experience|1`, `[GetPlayer.GetTag]`,
  `\n`, экранированные `\"`) — ровно как в оригинале.

## Шаг 1. Перевести

```bash
# 1. Сначала посмотреть, что инструмент вообще увидит — ничего не пишет и не ходит в сеть
hoi4-translator --src "C:\Games\mod\MyMod" --dst "D:\work\MyMod-ru" --target ru --dry-run

# 2. Перевести
hoi4-translator --src "C:\Games\mod\MyMod" --dst "D:\work\MyMod-ru" --target ru

# 3. Если мод большой и часть строк уже переведена — догнать остальное
hoi4-translator --src "C:\Games\mod\MyMod" --dst "D:\work\MyMod-ru" --target ru --skip-translated
```

Полезное на этом шаге:

* `--glossary terms.tsv` — закрепить термины (страны, дивизии, сокращения), чтобы
  движок не переводил их по-своему каждый раз;
* `--vanilla "…\Hearts of Iron IV\localisation"` — брать готовые официальные
  переводы вместо машинного;
* `--broken-lines keep-original` — если в исходнике есть строки со «сырыми»
  кавычками, не терять файл целиком, а оставить такие строки английскими;
* `--concurrency 5` — если Google начал отвечать 429 (слишком часто).

Результат — `D:\work\MyMod-ru\localisation\russian\*.yml`. Это уже почти мод:
не хватает только файла описания.

## Шаг 2. Собрать мод

Сборка одной командой: инструмент сам делает папку мода, `descriptor.mod` и
`.mod`, а с `--install` ещё и кладёт их в папку модов игры.

```bash
hoi4-translator \
  --src "C:\Games\mod\MyMod" \
  --dst "C:\Games\mod\MyMod-ru" \
  --target ru \
  --make-mod "MyMod — русский перевод" \
  --mod-target "C:\Games\mod\MyMod\descriptor.mod" \
  --install
```

* `--make-mod "Имя"` — имя в лаунчере; включает сборку. Имя папки и `.mod`-файла
  выводится из него латиницей, с языковым суффиксом (`MyMod_ru`): без суффикса
  перевод занял бы имя мода-цели и `--install` затёр бы его. Задать вручную:
  `--mod-folder MyMod_ru`.
* `--mod-target <descriptor.mod>` — оттуда берутся `dependencies` (чтобы перевод
  грузился вместе с модом-целью) и `supported_version`. Можно указать и папку
  мода-цели.
* `--install` — скопировать готовое в
  `Documents/Paradox Interactive/Hearts of Iron IV/mod`. Своя предыдущая версия
  перезаписывается; чужая папка с тем же именем не тронется — сборка остановится
  с объяснением.
* `--install-dir <dir>` — если папка модов лежит не там (портативная установка,
  нестандартный профиль).
* `--mod-version 1.0.0` и `--mod-supported-version "1.*"` — если нужно иначе, чем
  в дескрипторе мода-цели.

Сборка идёт только после успешного перевода: если хоть один файл не записан,
мод не собирается — иначе в лаунчер уехал бы перевод с дырами. Ошибки в списке
ключей видны до начала работы: имя папки, версия и дескриптор проверяются до
первой переведённой строки.

`--dst` может быть как корнем перевода (внутри `localisation/`), так и самой
папкой языка (`.../localisation/russian`) — файлы находятся в обоих случаях.

Что появится в `--dst` (для примера выше — в `MyMod-ru`):

```
MyMod-ru/
├─ MyMod_ru.mod                 ← описание для лаунчера, лежит в mod/
└─ MyMod_ru/
   ├─ descriptor.mod            ← то же описание, но без строки path
   └─ localisation/
      └─ russian/
         ├─ events_l_russian.yml
         └─ units_l_russian.yml
```

Перед сборкой файлы проверяются, и при первой же проблеме мод не собирается, а
инструмент говорит, какой файл виноват: не UTF-8 с BOM, первая строка не
`l_russian:`, нет ни одного файла `*_l_russian.yml`. Имя папки тоже проверяется —
пробелы и кириллица в пути запрещены: лаунчер такой мод просто не увидит.

## Шаг 2а. Если собираете руками

Иногда проще разложить вручную (например, мод уже лежит в папке игры).

Содержимое `MyMod_ru/descriptor.mod`:

```
name="MyMod — русский перевод"
version="1.0.0"
supported_version="1.*"
tags={
	"Translation"
}
dependencies={
	"MyMod"
}
```

`MyMod_ru.mod` — тот же текст плюс `path` в конце:

```
path="mod/MyMod_ru"
```

Три правила, на которых чаще всего спотыкаются:

1. **Имя папки и имя `.mod`-файла — латиница без пробелов.** Кириллица или
   пробел в пути — лаунчер такой мод не подхватит.
2. **`descriptor.mod` и `.mod` совпадают**, кроме `path`: `path` есть только в
   `.mod`, иначе лаунчер перезаписывает дескриптор и настройки теряются.
3. **`dependencies` — это `name=` из `descriptor.mod` мода-цели**, а не имя его
   папки. `supported_version` тоже бери у мода-цели (или `"1.*"`).

Если переводите ванилу, `dependencies` не нужен: моды читаются после базовой
игры, поэтому совпадающие ключи просто подменяются.

Не копируйте в мод перевода оригинальные `.yml`: смысл конструкции в том, что
здесь лежит **только** перевод.

## Шаг 3. Установить

Положите обе части (`MyMod_ru.mod` и папку `MyMod_ru/`) в папку модов:

* Windows: `%USERPROFILE%\Documents\Paradox Interactive\Hearts of Iron IV\mod\`
* Linux: `~/.local/share/Paradox Interactive/Hearts of Iron IV/mod/`
* macOS: `~/Documents/Paradox Interactive/Hearts of Iron IV/mod/`

Дальше — лаунчер: включить мод в плейсете. Перевод должен грузиться **после**
мода-цели; в плейсете его можно перетащить ниже. Если лаунчер упорно ставит его
раньше — переименуйте папку и файл с префиксом `zz_` (лаунчер сортирует по
имени). Язык игры — русский (лаунчер или настройки в игре).

## Шаг 4. Проверить

* Мод виден в лаунчере и включается — иначе смотрите «Частые ошибки» ниже.
* В игре вместо `GER_some_key` — нормальный текст.
* Если что-то не так, игра пишет причину в
  `Documents\Paradox Interactive\Hearts of Iron IV\logs\error.log` — ищите строки
  со словом `localisation`.
* Быстрая проверка без запуска игры — тот же инструмент по папке перевода:

  ```bash
  hoi4-translator --src "…\mod\MyMod_ru" --dst check --target ru --source-lang ru --dry-run
  ```

  Он покажет битые строки, дубли ключей и незакрытые `§`.

## Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| Мода нет в лаунчере | нет `MyMod_ru.mod` в `mod/`; пробел или кириллица в имени; `path` указывает не туда | имя латиницей, `path="mod/MyMod_ru"` |
| В игре видны «сырые» ключи | файл назван не `*_l_russian.yml`, первая строка не `l_russian:`, или в игре выбран другой язык | сверить имя файла, заголовок и язык игры |
| Кракозябры вместо русских букв | файл сохранён не в UTF-8 (потерян BOM) после правки в редакторе | пересохранить в «UTF-8 с BOM» |
| Часть строк осталась английской | этих ключей нет в переводе (например, переводили с `--skip-translated` по неполному результату) | прогнать без `--skip-translated` |
| Игра ругается на локализацию | битая строка: незакрытая кавычка или `§` | `--dry-run` по папке перевода, посмотреть номера строк |
| Перевод «не побеждает» мод-цель | перевод грузится раньше оригинала | переставить порядок в плейсете или префикс `zz_` |

## Что осталось автоматизировать

Сборка мода уже в инструменте. Дальше по этому пути логично:

* проверка порядка загрузки: предупредить, если в плейсете перевод окажется
  раньше мода-цели (лаунчер это хранит в своих настройках);
* публикация в Workshop — отдельная история, и лучше не в CLI.

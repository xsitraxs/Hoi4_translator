**Перевод модов Hearts of Iron IV пачкой, а не руками.** Инструмент проходит по `.yml`-файлам локализации, переводит только значения (ключи остаются как есть) и не ломает разметку Paradox: `$VALUE$`, `§R…§!`, `£money`, `[GetTag]`, `\n`. Перед записью каждый файл проверяется — сломанный перевод не попадёт в игру.

**Читать на других языках:** [English](README.en.md)

### 🔒 Безопасно ли запускать EXE?

Антивирусы и SmartScreen иногда ругаются на сборки PyInstaller — это ожидаемо, но проверять всё равно нужно:

* **Откуда файл.** EXE собирается GitHub Actions из открытого кода; ссылка на конкретный прогон CI указана в описании релиза.
* **Контрольная сумма.** К релизу прикладывается `SHA256SUMS.txt` с хешами EXE и JAR. Сверьте локально:
  ```powershell
  certutil -hashfile Hoi4_Translator.exe SHA256
  ```
  В Linux/macOS: `sha256sum -c SHA256SUMS.txt`. Если файла в релизе нет (старые версии), команда выше посчитает хеш, а сверить его можно с записью в описании релиза.
* **SmartScreen.** Файл не подписан сертификатом (это платно), поэтому Windows покажет «Windows защитила ваш компьютер»: «Подробнее» → «Выполнить в любом случае».
* **VirusTotal.** Если ссылка на отчёт есть в описании релиза — проверьте файл там; для сборок, запущенных из исходников, это не требуется.
* **Совсем без доверия к бинарнику.** Код открыт под MIT — запустите из исходников (Python 3.9+), результат будет тот же.

### Как выглядит результат

Ключи не трогаются, маркеры остаются на месте — меняется только текст:

```yml
# было (en)
l_english:
 GER_rearm_the_rhine:0 "Rearm $STATE$ with £army_experience|1 and [GetPlayerTag] backing."
 USA_war_goal_ussr:0 "§YDeclare war§! on $TARGET$ and gain §G+10%§! war support."
 GER_day_of_infamy:0 "Our diplomats call it \"an incident\".\nThe press calls it war."

# стало (ru)
l_russian:
 GER_rearm_the_rhine:0 "Перевооружите $STATE$ с помощью £army_experience|1 и поддержки [GetPlayerTag]."
 USA_war_goal_ussr:0 "§YОбъявите войну§! государству $TARGET$ и получите §G+10%§! поддержки войны."
 GER_day_of_infamy:0 "Наши дипломаты называют это \"инцидентом\".\nПресса называет это войной."
```

Если движок испортит хотя бы один маркер, строка попадёт в отчёт, а файл по умолчанию не запишется вовсе.

## 🚀 Основные возможности

* **Интеллектуальный перевод:** Google Translate и MyMemory через `deep-translator`; DeepL через официальный Python-клиент DeepL; дополнительный движок JavaSim.
* **Глоссарий терминов:** файл `термин → перевод` (TSV/CSV/JSON). Термины подменяются маркерами *до* отправки в движок и возвращаются уже переведёнными — движок не может их перевести иначе, переставить или просклонять. Пример: [`docs/glossary-example.tsv`](docs/glossary-example.tsv).
* **Переиспользование ванильных переводов:** указываете папку `localisation` установленной игры — строки, которые мод скопировал из базы (названия фокусов, типы дивизий, интерфейс), берут официальный перевод и вообще не уходят в движок. Быстрее, дешевле и без второго варианта перевода одного и того же термина.
* **Режим без интерфейса (CLI):** `python hoi4_translator.py --cli --src ... --dst ... --target ru` — для CI, скриптов и серверов без экрана.
* **Защита синтаксиса Paradox:** Автоматическое экранирование и сохранение игровых плейсхолдеров:
    * Переменные и форматтеры: `$VALUE$`, `$$`, `[GetTag]`, `[?value|%G0]`
    * Цветовые коды: `§R`, `§W`, `§!`, градиенты `§0`–`§9`
    * Иконки и кадры: `£money`, `£GFX_army|1`
    * Экранирование: `\n`, `\t`, `\"`
* **Гибридная архитектура:** Асинхронные сетевые запросы через `aiohttp`; JavaSim доступен как дополнительный движок через `JPype`.
* **Умное кэширование:** База данных SQLite хранит все выполненные переводы, экономя трафик и время при повторном запуске.
* **Продвинутый GUI:** Интерфейс на `tkinter` с логами в реальном времени, двойным прогресс-баром, статус-баром и предпросмотром перед сохранением.
* **Современный интерфейс:** GUI построен на [CustomTkinter](https://customtkinter.tomschimansky.com) — скруглённые виджеты, корректное масштабирование на HiDPI, аккуратная типографика, тёмная тема с янтарным акцентом.
* **Оформление в одном месте:** вид виджетов задаёт файл темы `hoi4translator/gui/amber.json` (янтарный акцент), а цвета, которых в теме нет (журнал, статусы, «зебра» предпросмотра), — палитра в `hoi4translator/gui/theme.py`. Акцент или любой оттенок меняется одной строкой. Окно предпросмотра следует той же теме.

## 🧱 Структура проекта

Код разложен по слоям; `hoi4_translator.py` остался точкой входа (`python hoi4_translator.py`) и реэкспортирует публичные имена пакета.

| Модуль | Отвечает за |
| --- | --- |
| `hoi4translator/config.py` | пути каталога данных, логи, атомарная запись, опциональные зависимости |
| `hoi4translator/localisation.py` | формат Paradox YML, имена языков HOI4, пути результата |
| `hoi4translator/text.py` | защита плейсхолдеров, разбиение длинных строк |
| `hoi4translator/validation.py` | проверка маркеров/цветов и отчёт валидации прогона |
| `hoi4translator/providers/` | коды языков движков и цепочка фолбэка |
| `hoi4translator/java_service.py` | сборка и вызов JAR-движка JavaSim |
| `hoi4translator/storage.py` | SQLite-кэш переводов и контрольные суммы исходника |
| `hoi4translator/translation.py` | `AsyncTranslator`: движки, ретраи, фолбэки |
| `hoi4translator/pipeline.py` | обработка одного файла: перевод, проверка, запись |
| `hoi4translator/report.py` | машинный отчёт о прогоне (`json`/`csv`) |
| `hoi4translator/settings.py` | настройки и ключи в системном хранилище |
| `hoi4translator/gui/` | окна tkinter (импортируются только при запуске GUI) |

## ⚙️ Особенности форматирования (Важно)

Инструмент формирует файлы по требованиям HOI4:
* **Языковая база:** В начало каждого выходного файла записывается соответствующий заголовок (`l_english:`, `l_russian:` и т. п.); имя файла заканчивается на `_l_<язык>.yml`.
* **Поддерживаемые цели:** Выбираются только встроенные базы HOI4, в том числе бразильский португальский `braz_por`.
* **Структура:** Ключи локализации не переводятся; значения записываются в одну строку, а игровые маркеры сохраняются.
* **Проверки перед записью:** Дубликаты ключей блокируют запись соответствующего файла, а совпадающие выходные пути — всю пачку до начала записи; цветовые маркеры проверяются на корректный формат, закрытие и исходный порядок.
* **Типографика:** Кавычки и пробелы в переводе форматируются с учётом целевого языка; плейсхолдеры и цветовые маркеры защищены от постобработки.
* **Предпросмотр:** Отмена предпросмотра не записывает текущий файл и явно отмечается в итоговом статусе.
* **Восстановление битых строк:** если перевод строки нарушает формат (движок «перевёл» маркер, потерял `$VALUE$`, вставил сырую кавычку), поведение задаётся полем «Битые строки»: `Не записывать файл` (по умолчанию) или `Заменить битую строку оригиналом` — тогда файл пишется, проблемная строка остаётся английской, а ключ попадает в отчёт и в лог. Восстановленные строки помечаются пустой контрольной суммой, поэтому при следующем запуске они переводятся заново, а не считаются готовыми.
* **Кодировка:** Файлы записываются в `UTF-8 BOM`, требуемой игрой для локализации. Исходники в `cp1251`/`cp1252`/`latin-1` читаются автоматически (с предупреждением в логе) и пересохраняются в UTF-8 BOM.

## 📦 Установка и запуск

### Запуск из исходников
1. Клонируйте репозиторий.
2. Установите Python 3.9+ и зависимости:
   ```bash
   python -m pip install -r requirements.txt
   ```
3. Запустите приложение:
   ```bash
   python hoi4_translator.py
   ```
   Для справки и проверки сборки: `python hoi4_translator.py --help` и `--version`.
4. **JavaSim.** JAR в репозитории не хранится — он собирается из `java/`:
   * автоматически при первом запуске, если установлен JDK (`javac`/`jar` в `PATH`); результат кэшируется в каталоге данных приложения и пересобирается при изменении исходника;
   * вручную:
     ```bash
     javac -d java java/com/hoi4/translator/HoI4Translator.java
     (cd java && jar cf ../hoi4_translator.jar com/)
     ```
   * либо готовый `hoi4_translator.jar` можно взять из артефактов CI или из релиза и указать в поле «Java JAR».

   JavaSim — дополнительный движок; перевод через Google, DeepL и MyMemory от него не зависит.

### Режим без интерфейса (CLI)

```bash
python hoi4_translator.py --cli \
  --src "MOD/localisation/english" \
  --dst "OUT/localisation/russian" \
  --target ru --engine Google \
  --glossary docs/glossary-example.tsv \
  --vanilla "C:/Steam/steamapps/common/Hearts of Iron IV/localisation"
```

Проверка без перевода и без интернета — `--dry-run`: разбирает файлы и показывает битые строки, дубликаты ключей и незакрытые `§`, ничего не записывая. Игра для этого не нужна.

Полезные ключи: `--skip-translated` (не переводить готовое), `--broken-lines keep-original`, `--concurrency N`, `--no-report`, `--quiet`. Полный список: `python hoi4_translator.py --cli --help`.

Коды возврата: `0` — всё записано, `1` — хотя бы один файл не записан (или `--dry-run` нашёл проблемы), `2` — ошибка аргументов или папок (перевод не начинался). Второй код удобно проверять в CI: неправильная папка не должна выглядеть как успешный прогон.

### Нет установленной игры?

Это не мешает: инструмент работает с `.yml`-файлами мода, сама игра не нужна. Необязательным остаётся только поле «Ваниль» (переиспользование официальных переводов). В репозитории есть демо-мод с «мини-ванилью», на котором можно прогнать всё целиком: [`docs/TESTING-WITHOUT-GAME.md`](docs/TESTING-WITHOUT-GAME.md).

### Структура папок
Выберите отдельные исходную и выходную папки. Сохраните одинаковый уровень корня: например, если источник — корень мода, выход тоже должен быть корнем отдельного мода; если источник — `localisation`, выберите выходной корень `localisation`. Приложение сохранит относительную структуру и заменит языковой каталог/суффикс на выбранный целевой язык.

## 🧠 Как работает кэш и режим «Пропускать переведённое»

* Кэш переводов — SQLite в каталоге данных приложения (см. ниже). Запись ключается на текст, пару языков и движок.
* **По умолчанию каждый движок читает только свой кэш.** Иначе смена Google → DeepL ничего бы не меняла: для уже переведённых строк вечно отдавался бы старый Google-текст. Галочка «Экономить трафик: переиспользовать кэш других движков» включает прежнее поведение.
* Кнопка **«Очистить кэш»** удаляет записи выбранного движка для текущей языковой пары.
* Режим «Пропускать переведённое» дополнительно хранит контрольную сумму исходной строки для каждого ключа выходного файла. Если автор мода изменил английский текст, сохранённый перевод считается устаревшим и строка переводится заново. Для файлов, записанных старыми версиями (контрольных сумм ещё нет), приложение сохраняет имеющийся перевод, но явно предупреждает, что сверить его с исходником нельзя.

## 🛡 Надёжность и диагностика

* **Цепочка фолбэка:** при отказе движка используется следующий (`DeepL → Google → MyMemory`, `Google → MyMemory`). Каждая подмена показывается в логе и попадает в итоговую строку статуса (`фолбэки: DeepL → Google: 12`), чтобы платный движок не подменялся бесплатным незаметно.
* **Ограничение по времени:** бюджет на файл зависит от числа строк (`60 с + 0.35 с/строка`, минимум 120 с). При превышении файл не записывается, а незавершённые запросы отменяются.
* **Отмена:** кнопка «СТОП» снимает незавершённые задачи, а не ждёт сетевых таймаутов.
* **Доступность движков:** движок, клиент которого не установлен, не предлагается в списке; причина (`pip install deepl` и текст ошибки импорта) выводится в лог при запуске. Установите зависимости командой `python -m pip install -r requirements.txt` — тогда DeepL и JavaSim появятся в списке движков.
* **Логи:** ротируемый файл `hoi4_translator.log` (1 МБ × 3) в каталоге данных; в GUI дублируются основные события. Содержимое переводимых строк в лог не пишется.
* **Отчёт о прогоне:** по завершении рядом с выходной папкой создаются `hoi4_translator_report_<дата>.json` и `.csv` (разделитель `;`, колонки `state;file;key;issues`). В JSON — итоги (файлы, записано/отклонено/отменено/ошибок, строки, пропущено, устарело, восстановлено, битых, фолбэки), список файлов с причиной отказа и список проблемных строк; в CSV — только проблемные строки (`recovered` — заменённые оригиналом, `broken` — подозрительные, но записанные). Список строк ограничен 500 записями, остальные только учитываются (`hidden_rows`). Файлы отчёта не создают каталогов: если выходной папки нет, прогон завершается без отчёта.

### Каталог данных

| ОС | Путь |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Hoi4Translator` |
| macOS | `~/Library/Application Support/Hoi4Translator` |
| Linux | `$XDG_DATA_HOME/Hoi4Translator` или `~/.local/share/Hoi4Translator` |

Там же лежат `settings.json` и `translation_cache.db`. **API-ключ DeepL в JSON не сохраняется** — только в системном хранилище учётных данных (Windows Credential Manager / Keychain / Secret Service).

## ⚠️ Известные ограничения

* Асинхронный путь Google использует неофициальный эндпоинт `translate.googleapis.com/translate_a/single`; его формат может измениться в любой момент (ретраи на 429 уже предусмотрены).
* MyMemory — последний фолбэк с жёсткими суточными лимитами.
* По умолчанию строка, нарушающая формат (например, движок «перевёл» маркер), блокирует запись всего файла: инструмент принципиально не пишет результат, который сломает игру. Режим `Заменить битую строку оригиналом` снимает это ограничение — см. раздел о форматировании.
* Окно предпросмотра показывает (и даёт отредактировать) первые 1000 строк файла; остальные сохраняются как перевёл движок.

## 👩‍💻 Разработка

```bash
python -m pip install -r requirements.txt ruff coverage
python -m ruff check hoi4_translator.py hoi4translator/ tests/
python -m unittest discover -s tests -v
python -m coverage run --source=hoi4translator -m unittest discover -s tests && python -m coverage report
```

Тесты описывают поведение (парсер формата, валидация маркеров, кэш, отмена, запись файлов), не детали реализации.

Отрисовать GUI в CI нельзя, поэтому `tests/tk_stub.py` подменяет tkinter и CustomTkinter записывающими заглушками: `tests/test_gui_smoke.py` собирает окно, проверяет наличие всех элементов управления, цвета журнала из палитры, долю прогресс-баров и построение предпросмотра. Заглушка сверяет опции виджетов с документацией CustomTkinter, поэтому опечатка в `fg_color`/`text_color` падает в тестах, а не у пользователя. Внешний вид эти тесты не проверяют — его по-прежнему нужно смотреть глазами.

CI (`.github/workflows/build.yml`) прогоняет тесты на Python 3.9/3.11/3.13, проверяет линтер, собирает JAR и (для тегов и ручного запуска) Windows-EXE, который затем проверяется запуском с `--help`.

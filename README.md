**Перевод модов Hearts of Iron IV пачкой, а не руками.** Инструмент проходит по `.yml`-файлам локализации, переводит только значения (ключи остаются как есть) и не ломает разметку Paradox: `$VALUE$`, `§R…§!`, `£money`, `[GetTag]`, `\n`. Перед записью каждый файл проверяется — сломанный перевод не попадёт в игру.

**Читать на других языках:** [English](README.en.md)

> **Версия 2.0 — переписана на Rust.** Ядро, движки перевода и CLI портированы с Python 1:1 (формат файлов, проверки, кэш, отчёты). Java больше не нужна: движок Google встроен. Настольное окно сейчас в работе — см. [Roadmap](#-roadmap): на этом этапе инструмент работает как `hoi4-translator` в консоли.

### 🔒 Безопасно ли запускать EXE?

* **Откуда файл.** Бинарник собирается GitHub Actions из открытого кода; ссылка на прогон CI есть в описании релиза.
* **Контрольная сумма.** К релизу прикладывается `SHA256SUMS.txt`. Сверьте локально: `certutil -hashfile hoi4-translator.exe SHA256` (Windows) или `sha256sum -c SHA256SUMS.txt` (Linux/macOS).
* **SmartScreen.** Файл не подписан сертификатом (это платно), поэтому Windows покажет «Windows защитила ваш компьютер»: «Подробнее» → «Выполнить в любом случае».
* **Совсем без доверия к бинарнику.** Код открыт под MIT — `cargo build --release` из исходников даёт тот же результат.

### Как выглядит результат

Ключи не трогаются, маркеры остаются на месте — меняется только текст:

```yml
# было (en)
l_english:
 GER_rearm_the_rhine:0 "Rearm $STATE$ with £army_experience|1 and [GetPlayerTag] backing."
 USA_war_goal_ussr:0 "§YDeclare war§! on $TARGET$ and gain §G+10%§! war support."
 GER_day_of_infamy:0 "Our diplomats call it \"an incident\".\nThe press calls it war."

# стало (ru)
l_russian:
 GER_rearm_the_rhine:0 "Перевооружите $STATE$ с помощью £army_experience|1 и поддержки [GetPlayerTag]."
 USA_war_goal_ussr:0 "§YОбъявите войну§! государству $TARGET$ и получите §G+10%§! поддержки войны."
 GER_day_of_infamy:0 "Наши дипломаты называют это \"инцидентом\".\nПресса называет это войной."
```

Если движок испортит хотя бы один маркер, строка попадёт в отчёт, а файл по умолчанию не запишется вовсе.

## 🚀 Возможности

* **Три движка и цепочка фолбэка:** Google (неофициальный HTTP-эндпоинт, без API-ключа), DeepL (официальный API, ключ `--api-key` или `DEEPL_API_KEY`), MyMemory. Отказ движка или битый ответ — повод передать **только эту строку** следующему движку: `DeepL → Google → MyMemory`, `Google → MyMemory`, `MyMemory → Google`.
* **Глоссарий терминов:** файл `термин → перевод` (TSV/CSV/JSON). Термины подменяются маркерами *до* отправки в движок и возвращаются уже переведёнными — движок не может их перевести иначе, переставить или просклонять. Пример: [`docs/glossary-example.tsv`](docs/glossary-example.tsv).
* **Переиспользование ванильных переводов:** укажите папку `localisation` установленной игры — строки, скопированные из базы (названия фокусов, типы дивизий, интерфейс), берут официальный перевод и вообще не уходят в движок.
* **Проверка без перевода и без интернета:** `--dry-run` разбирает файлы и показывает битые строки, дубликаты ключей и замечания по `§`.
* **Кэш SQLite:** одинаковые строки не переводятся дважды; режим `--skip-translated` помнит контрольную сумму исходника, поэтому изменённая английская строка переводится заново.
* **Отчёт о прогоне:** JSON + CSV рядом с выходной папкой — что записано, что отклонено, что заменено оригиналом, сколько было фолбэков.
* **Атомарная запись:** файл заменяется целиком (временный файл + `rename`), игру нельзя застать за чтением половины строки.
* **Без Java и Python:** один самодостаточный бинарник; SQLite вкомпилирован.

## ⚙️ Особенности форматирования (важно)

* **Языковая база:** в начало каждого выходного файла пишется заголовок (`l_english:`, `l_russian:`), имя файла заканчивается на `_l_<язык>.yml`.
* **Поддерживаемые цели:** только встроенные базы HOI4, включая бразильский португальский `braz_por`.
* **Ключи и ревизии:** `KEY:0` и `KEY:7` — один и тот же ключ (число после двоеточия — номер ревизии), поэтому такие строки считаются дубликатами и блокируют запись файла.
* **Проверки перед записью:** дубликаты ключей блокируют файл, совпадающие выходные пути — всю пачку до начала записи; цветовые маркеры проверяются на корректный формат, закрытие и исходный порядок.
* **Чьи ошибки блокируют файл:** только то, что испортил движок. Если цвет в исходнике не закрыт (мод закрывает его через `$ПЕРЕМЕННУЮ$`) или значение — одинокий `§R`, строка записывается как есть с предупреждением.
* **Реальные файлы:** значение заканчивается на последней кавычке строки, поэтому неэкранированные кавычки внутри текста не рвут разбор; `§[выражение]` — динамический цвет, `§§` — обычный знак `§`. Проверено на 110 файлах и 213 623 ключах из Kaiserreich и Millennium Dawn.
* **Типографика:** кавычки и пробелы форматируются с учётом целевого языка (`«…»`, `„…“`, `“…”`, `「…」`); плейсхолдеры и цветовые маркеры защищены от постобработки.
* **Битые строки:** `--broken-lines reject` (по умолчанию) не пишет файл; `--broken-lines keep-original` пишет файл, оставляет проблемную строку английской и перечисляет её в отчёте. Восстановленные строки помечаются пустой контрольной суммой, поэтому при следующем запуске они переводятся заново, а не считаются готовыми.
* **Кодировка:** файлы записываются в `UTF-8 BOM`. Исходники в `cp1251`/`cp1252`/`latin-1` читаются автоматически (с предупреждением в логе) и пересохраняются в UTF-8 BOM.

## 📦 Установка и запуск

### Базовый прогон

```bash
hoi4-translator \
  --src "MOD/localisation/english" \
  --dst "OUT/localisation/russian" \
  --target ru --engine Google
```

Проверить файлы, ничего не переводя и не выходя в интернет:

```bash
hoi4-translator --src examples/demo-mod --dst /tmp/out --target ru --dry-run
```

Готовый демо-мод с «мини-ванилью» лежит в репозитории: [`docs/TESTING-WITHOUT-GAME.md`](docs/TESTING-WITHOUT-GAME.md).

### Полезные ключи

| Ключ | Что делает |
| --- | --- |
| `--engine Google\|DeepL\|MyMemory` | движок перевода (по умолчанию Google) |
| `--api-key KEY` / `DEEPL_API_KEY` | ключ DeepL; без него `--engine DeepL` завершится с кодом 2 |
| `--glossary FILE` | глоссарий терминов (TSV/CSV/JSON) |
| `--vanilla DIR` | папка `localisation` игры — переиспользовать официальные переводы |
| `--skip-translated` | не переводить то, что уже переведено в папке результата |
| `--broken-lines reject\|keep-original` | что делать со строкой, сломавшей формат |
| `--concurrency N` | параллельных запросов (по умолчанию 15) |
| `--no-report` | не создавать JSON/CSV отчёт |
| `--quiet` | только итог, без строк файлов |
| `--dry-run` | только разбор файлов, без перевода и записи |
| `--make-mod NAME` | собрать готовый мод: папка, `descriptor.mod`, `.mod` (см. [`docs/MAKE-A-TRANSLATED-MOD.md`](docs/MAKE-A-TRANSLATED-MOD.md)) |
| `--mod-folder NAME` | имя папки и `.mod`-файла (латиница без пробелов) |
| `--mod-target PATH` | дескриптор мода-цели: оттуда `dependencies` и `supported_version` |
| `--mod-version X.Y.Z` | версия мода перевода (по умолчанию 1.0.0) |
| `--mod-supported-version X.Y.*` | `supported_version` в дескрипторе |
| `--install` | скопировать готовый мод в папку модов игры |

Полный список: `hoi4-translator --help`.

### Коды возврата

| Код | Значение |
| --- | --- |
| `0` | всё записано |
| `1` | хотя бы один файл не записан (или `--dry-run` нашёл битые строки и дубликаты) |
| `2` | ошибка аргументов или папок — перевод не начинался |

Второй код удобно проверять в CI: неправильная папка не должна выглядеть как успешный прогон.

### Структура папок

Выберите отдельные исходную и выходную папки: вложенность запрещена (иначе прогон перечитывал бы собственный результат). Сохраняйте одинаковый уровень корня: если источник — корень мода, выход тоже должен быть корнем отдельного мода; если источник — `localisation`, выходной корень `localisation`. Относительная структура сохраняется, а языковой каталог и суффикс заменяются на выбранный язык.

## 🧠 Кэш и режим «Пропускать переведённое»

* Кэш — SQLite `translation_cache.db` в каталоге данных приложения. Ключ записи: текст + пара языков + движок.
* **По умолчанию каждый движок читает только свой кэш:** иначе смена Google → DeepL ничего бы не меняла и для готовых строк вечно отдавался бы старый Google-текст.
* Кэш помечен версией формата (`2`): после изменения правил проверки или типографики старые записи перестают использоваться. Записи, сделанные Python-версией 1.4.x, совместимы — повторно переводить мод после обновления не нужно.
* `--skip-translated` дополнительно хранит контрольную сумму исходной строки для каждого ключа выходного файла. Изменённый английский текст считается устаревшим и переводится заново; для файлов без контрольных сумм перевод сохраняется с предупреждением, что сверить его с исходником нельзя.

## 🛡 Надёжность и диагностика

* **Фолбэк на битый ответ:** ответ, который нельзя записать в игру (потерян `$STATE$`, нарушен формат строки), — неудачная попытка, а не перевод: строка уходит к следующему движку, остальные не пересчитываются. В кэш попадает только перевод, прошедший проверку.
* **Ограничение по времени:** бюджет на файл — `60 с + 0.35 с/строка`, минимум 120 с. При превышении файл не записывается, а незавершённые запросы прекращаются.
* **Параллельность:** до `--concurrency` строк переводятся одновременно; остановка (`Ctrl+C`) завершает процесс, недописанных файлов не остаётся благодаря атомарной записи.
* **Отчёт о прогоне:** рядом с выходной папкой создаются `hoi4_translator_report_<дата>.json` и `.csv` (разделитель `;`, колонки `state;file;key;issues`). В JSON — итоги (файлы, записано/отклонено/отменено/ошибок, строки, пропущено, устарело, взято из ванили, восстановлено, битых, фолбэки), список файлов с причиной отказа и проблемные строки; в CSV — только проблемные строки. Список ограничен 500 записями, остальные только учитываются (`hidden_rows`). Отчёт никогда не создаёт каталогов и не срывает прогон.
* **Логи:** `hoi4_translator.log` в каталоге данных плюс вывод в консоль. Содержимое переводимых строк в лог не пишется.

### Каталог данных

| ОС | Путь |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Hoi4Translator` |
| macOS | `~/Library/Application Support/Hoi4Translator` |
| Linux | `$XDG_DATA_HOME/Hoi4Translator` или `~/.local/share/Hoi4Translator` |

Там же лежат `translation_cache.db` и `hoi4_translator.log`. Ключ DeepL хранится только в переменной окружения или аргументе командной строки — в файлы он не пишется.

## ⚠️ Известные ограничения

* **Настольного окна пока нет:** версия 2.0 — это CLI. Графический интерфейс портируется отдельным этапом (см. Roadmap); вся логика перевода для него уже выделена в библиотеку.
* Google используется через неофициальный эндпоинт `translate.googleapis.com/translate_a/single`; его формат может измениться (ретраи на 429 предусмотрены).
* MyMemory — последний фолбэк с жёсткими суточными лимитами.
* Устаревшие флаги: `--cli` принимается и игнорируется, `--engine JavaSim` работает как `Google` (с предупреждением), `--java-jar` игнорируется.
* `cp1252`-файлы без BOM читаются как `cp1251` — как и в Python-версии; при необходимости пересохраните файл в UTF-8.

## 👩‍💻 Разработка

```bash
cargo fmt --all
cargo clippy --all-targets
cargo test
cargo build --release
```

Тесты описывают поведение (парсер формата, валидация маркеров, глоссарий, кэш, запись файлов, коды возврата), а не детали реализации. Тесты никогда не ходят в сеть: значения, которые нужно перевести, либо закреплены глоссарием, либо являются чистой разметкой.

CI (`.github/workflows/build.yml`) на каждый pull request прогоняет `clippy` и `cargo test`
(юнит-тесты модулей плюс `tests/cli_integration.rs`), затем запускает настоящий бинарник
на демо-моде в режиме `--dry-run` — это проверяет парсер, CLI и коды возврата без сети.
`cargo fmt --check` блокирующий, но pull request из этого же репозитория job исправляет
сам: код 2.0 писался там, где Rust-тулчейна не было, поэтому шаг «Format the branch»
прогоняет `cargo fmt --all` и добавляет `Cargo.lock`, если их нет, и коммитит результат
в ветку. Для форков и остальных запусков форматирование только проверяется.

Windows-бинарник собирается для тегов и ручного запуска, проверяется запуском с `--help`
и публикуется в релизе вместе с `SHA256SUMS.txt`. `Cargo.lock` лежит в репозитории, так что
у всех собирается один и тот же набор версий зависимостей.
